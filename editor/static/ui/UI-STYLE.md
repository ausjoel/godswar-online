# gwadmin-web UI style guide: make the editor look like the game

Written 2026-10-28 (task "windows"). This is the style guide and component
spec for the reborn editor pages of gwadmin-web. It says which in-game window
each editor page should copy, and gives the measurements, art, fonts, colours
and tooltip format to copy it with.

Everything here comes from the admin's client,
`GodsWar-2.51/Reborn-Client/Client` (the Godswar Origin client with the reborn
patches). The rules for reading its layouts are in
`GodsWar-2.51/Client-RE/origin/UI-SYSTEM.md`.

Evidence marks, as in UI-SYSTEM.md:

- **[M]** measured: read from the client files, from a render made by
  `build_ui_kit.py`, or from the live database (read-only).
- **[S]** read from code: `Origin.exe` string references, or Lua.
- **[I]** inferred: likely, not proven.

---------------------------------------------------------------------------

## 1. What is in this folder

Everything is generated by `gwadmin-web/build_ui_kit.py`. Run it on the Mac,
because it needs the client and Pillow:
`python3 -I build_ui_kit.py`. The VPS needs neither, because the outputs are
checked in. Do not edit the generated files by hand.

| File | What it is |
|---|---|
| `windows/<key>.png` | A window rebuilt from its layout XML: the frame, pictures, labels and empty cells, with the first tab open. It is a **reference picture, not a screenshot**. Values the game's code fills in, item and skill icons, and hidden elements are not drawn. Labels such as `12345678`, `Athena` or `战士战士` are the developers' own placeholder text in the XML. |
| `windows/<key>--<tab>.png` | The same window with another tab open, for example `bags--mount.png` or `skills--talent.png`. |
| `windows.json` | Every element of the 36 windows in §6: its absolute rectangle (`l,t,r,b` in design pixels, with the window's top-left at 0,0), type, `ID`, picture (atlas and x,y), icon-on-top, font and size, colour constant, text, alignment (`TextFormat`), events and visibility. Each window also has `screen_rect` (where the game opens it on a 1024x768 screen), `grids` (detected slot grids) and `tab_pages`. |
| `sprites.png`, `sprites.json` | 48 reusable pieces cut from `UI/Texture/main.gwo`: cells, buttons with their state rows, tabs, check boxes, arrows, bars, stars, camp emblems, the HUD frame and the paperdoll figure. `sprites.json` gives each piece's place in the sheet, its source rectangle in `main.gwo`, its frame count and the layouts that use it. |
| `frames/T_*.png` | The six window frames, each assembled as a 3x3 picture for CSS `border-image`. |
| `zodiac/00.png` .. `11.png` | The 12 zodiac pictures (`UI/Texture/000.gwo` .. `011.gwo`, 256x256, saved at 128x128). Sign `v` uses `0vv.gwo`, as in `Constellation.lua` `synconstype()` [S]. |
| `palette.json` | Every colour in `font.lua`, with the quality, grade and pet-aptitude tables from `ItemColor.xml`, grades 14-25 from the server, font sizes, zodiac sign names and class names. |
| `ui-kit.css` | CSS custom properties for every colour, a `.gw-<name>` class for every sprite (hover, `.on`/`.selected` and `.disabled` states use the state rows), `.gw-frame-*` frames, and the helpers `.gw-q1..20`, `.gw-g1..25`, `.gw-apt1..20`, `.gw-text`, `.gw-label`, `.gw-value`, `.gw-outline` and `.gw-tooltip`. |
| `demo.html` | A gallery of all the components, used to check the CSS. |

The item and skill icons are already in `static/icons-origin.png` (the
`Icon.gwo`..`Icon4.gwo` atlases, 2 x 2) and `catalog-origin/*.json`
(`build_origin_catalog.py`). This kit does not duplicate them. Use
`static/origin-ui.png` (the whole of `main.gwo`) only for a piece that is
not yet in the sprite sheet; to add one, put it in `SPRITES` in the builder.

## 2. The game's look in one page

- **Design space.** Every window is laid out in a fixed 1024 x 768 space, and
  on the admin's Mac 1 design pixel is 1 screen pixel [M, UI-SYSTEM §2]. Build the
  editor's game-like panels in the same pixels: a bag cell is 42 x 42, a
  normal window is 263-350 wide. Offer a page zoom of 100 / 125 / 150 %
  (CSS `zoom` on the panel). Do not change the layout's numbers to scale it.
- **Windows** are dark, translucent slate-blue panels. Big windows use the
  stone frame `T_NormalWindow`, which has two gargoyles on a black title bar
  and a thin silver rule. Dialogs and sub-panels use `T_SimpleWindow`, which
  has a 17 px silver rounded border. Tooltips use `T_BgWindow`, a 7 px border.
  Window bodies are `rgba(4,18,30,0.8)` [M: `main.gwo` pixel (176,96) =
  4,18,30,204].
- **Inside a window**, related values sit in `T_SimpleWindow` sub-panels. The
  character window, for example, has five: status, guild, level, and the two
  stat columns.
- **Text** is small and monospaced: Latin glyphs in the TTF are Consolas [M,
  UI-SYSTEM §6].
  - Most labels use `MainMap` (10 px).
  - Window titles and buttons use `MainFonts` (12 px).
  - Big buttons and tabs use `Mainlogin2` (14 px).
- **Label and value colours.** In data windows a label is
  `BASE_HEADCOLOR` #6bccfe (light blue) and its value is
  `ORDINARY_INFOCOLOR` #fff77c (pale yellow): character 29 labels / 26
  values, inspect window 18 / 18 [M]. A window title is `YELLOW_TEXTCOLOR`
  #ffff00. Plain text and buttons are white. Bad values and warnings are
  `GWORed` #ff0000, and bonuses are `GREEN_TEXTCOLOR` #00ff00.
- **Text outline.** `TextWeight` 1-3 draws a black outline. Use
  `.gw-outline` on text that sits over pictures, such as stack counts on
  cells.
- **Cells.** Every item, skill and pet slot is the same 42 x 42 stone cell
  (`main.gwo` 0,540). An icon is 36 x 36 and is drawn 3 px in from the cell's
  edge (`BtnTopRect="3,3,39,39"`) [M].
  - The cell's frames are: row 0 normal, row 1 hover (blue rim), row 2
    pressed.
  - There is no disabled frame. The fourth row is empty [M], so show
    disabled cells with `opacity: .35`.
- **Buttons** are 4-row sprites: normal (dark blue glass), hover (cyan glow),
  pressed (cream) and disabled (grey) [S UI-SYSTEM §5.2; M].
- **Tabs** use the same 4 rows. The selected tab is the cream row [M]; the
  chat-channel tab "World" in `Reborn-Client/verification/06-in-world-later.png`
  shows it.
- **Check boxes** have 4 rows: unchecked, an unused row, checked (a red tick)
  and disabled.
- **Scrolling lists** have a 24 px track on the right, with the caps
  `scroll-top` and `scroll-bottom`, the 1 px `scroll-mid` stretched between
  them, and the arrow buttons `arrow-up` and `arrow-down` over the caps.
- **Inline colour codes.** Game text switches colour with `|cAARRGGBB`
  (for example `|cFFDCC883 Effect |cFFFFFFFF`) [M]. When the editor shows
  client text (item descriptions, quest text, holy-suit names), it must turn
  those codes into `<span style="color:#RRGGBB">` with text nodes. Never use
  `innerHTML`: the text is data.

### 4.2 The item tooltip's content, in order

The order comes from the order in which the tooltip code at
0x57ef00-0x582b10 in Origin.exe references its caption keys [S]. The caption
text is the English value of those keys in `Text/EquipDescription.dat` and
`Message.dat` [M]. The exact spacing and number formats are not verified at
run time [I].

1. **Name**, in the quality colour (§3.2). Lines 2 and 3 sit on one row:
   **Part** on the left (the slot: `Heads` "Helmet", `Armors` "Armor",
   `Mounthead` "Mount Coronet" ...) and **weapon type** on the right
   (`Swords` "One-Hand Sword", `TwoHandsAxes` "Two-Hand Axe" ...).
2. **Description**: the item's `EquipDescription.dat` text, with its
   `|c` codes.
3. **Binding**: `Binding` = "|cFFFFFF00Can't be traded" (yellow) or
   `UnBinding` = "Can be traded".
4. **Level requirement**: `Level1` "Lv." + the level.
5. **Mount** line (mount items).
6. **Class restriction**: `Class` "Class Restriction" + `Class0..3`
   Warrior / Champion / Priest / Mage, or `AllClass`.
7. **Gender** (`SexBind0` Female / `SexBind1` Male) and **camp** (`Camp0`
   Sparta / `Camp1` Athens) restrictions.
8. **Grade**: `AppendStar` "Grade" + one ★ (`Message.dat` `Star`) per
   grade, in the grade colour (§3.3).
9. **Base attributes**, white. Examples: `Attack` "Physical Attack",
   `Defence` "Physical Defense", `MagicAk` "Magical Attack". Rates are
   printed with `%.1f`, and lines are joined with `|` [S].
10. **Append attributes**, green, with their level, for example
    `AttackF` "(Lv.5)Attack+".
11. **Refining**: `AddProbability` "Add-Refining Chance", and the
    life-skill / make information.
12. **Price**: `Money` Silver, `Stone` Gold, `BindingGold` B-GOLD, `NeedMoney`
    / `NeedStone` / `NeedBindingGold` / `NeedSimplePoint` / `NeedMedalPoint`;
    in shops also `OldStone` "Original Price", `NewStone` "Current Price" and
    `Discount`.
13. **Pet / mount bonuses**: `MaxHPD` "Max HP Bonus", `HitD`, `MissD`,
    `StateD`, `FuryAddAk` ... and `Speed`.
14. **Time limit**: `ThisItem`, then `Day` / `Hour` / `Minute` and
    `AutoDisappear`.
15. **Holy suit**: `Suit%d`, for example `Suit403` "|cFF16D9FFLevel 3
    Platinum". Then `SuitAddEffect` "Increase the effectiveness of the
    equipment", `SuitCurExp` "Current EXP of the equipment" and
    `SuitUpGradeExp` "EXP or Experience Prism needed for the upgrade".
16. **Holy stones (sockets)**: for each socket, the stone icon (`StoneBtn`)
    and `EquipStoneLevName` "Holy Stone" + "Lv." + level +
    `EquipStoneName<n>` (for example "Fire Spirit of Destruction") +
    `EquipStoneDesc<n>`. An empty socket reads `EquipStoneDesc0` "Not
    enchased".
17. **Container items**: `SpecialExpBall` / `SpecialBijouBag` /
    `SpecialMoneyBag` "Current accumulated EXP / Gold / Silver".

`ui-kit.css` has `.gw-tooltip` (dark box, white 12 px monospace, 280 px
max) plus `.tt-name`, `.tt-green` (append lines), `.tt-bound` (yellow) and
`.tt-bad` (red). Add the editor-only lines **after** the game lines,
separated by a thin rule and in `#8aa`: item id, template kind, DB columns,
stack/Overlap.

### 4.3 Field help (the "what is CdKey?" problem)

Every label in an editor page gets hover help in the `UIHelper` style. Write
it in plain English, in three short parts:

```
Talent points (SkillPoint)
Points the player spends in the Talent tree (K > Talent). 0 - 2,147,483,647.
Stored in character_base.SkillPoint. Changing it does not refund talents.
```

1. The game's own words for the field, with the DB column in brackets.
2. What it does and its range, taken from the CHECK constraint or the
   source (README §8.3).
3. Where it is stored, and any side effect (revision bump, invariants).

Fields that only the server sees (`checkpoint_owner_id`, `*_revision`,
evidence tables) say "server bookkeeping - read-only" and why. The 1.0-only
`CdKey` column does not exist in reborn, so it must not appear on reborn
pages.

### 5.1 The library / picker grid (the admin's follow-up)

The game's own "many items" window is the Mall (`MallUIConfig.xml`). It has
6 tiles per row; each tile is 85 x 83 (a `T_SimpleWindow` background 83 x
83). Inside a tile [M]:

- a 42 px cell at tile 7,10;
- the name at 53,10, 77 px wide, 10 px text;
- the second line (discount) at 55,43;
- the price at 7,62.

The window has 8 category tabs across the top, a scroll track on the right
and a bottom bar with the money field and Buy / Recharge buttons.

The editor's picker copies it, scaled up to the full page:

- **Tiles:** 6-12 columns depending on the width. Each tile shows the cell
  and icon, the name in its quality colour (§3.2), and one grey line with
  "#id · Lv n · kind".
- **Tabs:** one per kind (Weapon, Armor, Accessory, Mount, Pet, Consumable,
  Material, Quest, Other ... from `item_templates.kind`). Then filter chips
  for class, level range and slot, and a search box over name, id and tag.
- **All entries:** the picker shows every entry of the type. For items that
  is 3,488 live `item_templates` [M], not a "top N". To stay fast, render
  only the visible rows (virtual scrolling: one tall spacer div, plus the
  tiles for `scrollTop / rowHeight ± 2` rows). Filter in memory, on the
  client.
- **Hover:** shows the item tooltip (§4.2). **Click:** picks the item.
  **Double-click:** picks it and closes.
- **Same picker everywhere:** skills, talents, pet skills, buffs, titles,
  quests and attributes use the same component with their own tile line,
  for example "Pet skill · Royal Dogs only".

### 5.2 Gear editor (sockets)

The game has no window that shows 6 holy sockets around an item. Holy stones
are fitted through NPC dialogs and are shown only in the tooltip. The
closest layout is the forge window's **Gems** tab (`EquipForgeExUI.xml`
`Bag1`), which has 6 cells in two rows of three at x 76 / 152 / 232, y 117 /
184, and the result cell below at 152,267 [M]. See `windows/forge--gems.png`.
The gear editor should use that geometry:

- the item cell is the "result" position;
- the 6 holy sockets are the 6 cells: socket 1-3 on the top row, 4-6 on the
  bottom row;
- sockets beyond `holy_socket_count` are drawn locked (`opacity:.35`) with
  "+ open socket" on hover.

Clicking a socket opens the Holy Stone picker (`EquipStoneName1..20` with
their `EquipStoneDesc`, levels 1-10). The append attributes (5 rows) and
the holy-suit tier sit beside it, in the tooltip's order (§4.2). The live
tooltip preview is always visible on the right.

## 8. Rules for the editor pages

1. **Copy the game's window** from §6 for every page that has one: the same
   frame, the same order of sections, the same cell size and spacing, the
   same tab names. the admin should recognise every page from the game.
2. **Use pictures instead of text** wherever the game does: cells with
   icons, bars, stars, the paperdoll, zodiac pictures, camp emblems.
3. **Name and colour items the game's way**: the name in its quality colour,
   the grade as ★ in its grade colour, append attributes in green, binding
   in yellow.
4. **Give every field hover help** (§4.3). Use the game's words first, the
   DB column second.
5. **Show why read-only things are read-only** in their hover help: sealed
   or published content, evidence tables, server bookkeeping. Draw them
   with `opacity:.55` and no hover glow.
6. **Online characters.** When `/admin/capabilities` says live edits are
   available, edit the character through the server. Otherwise show the
   game's grey "disabled" state on the whole page, with "log the character
   out to edit" as its hover help.
7. **Treat client and DB text as data.** Item names, descriptions, quest
   text and player names are inserted as text nodes. `|c` codes become
   spans (§2); nothing else is interpreted.

## 9. Wiring it into gwadmin-web (not done here)

`server.py` serves `/static/<name>` by **basename only**
(`os.path.basename(u.path)`, around line 1169). So `/static/ui/ui-kit.css`
would be looked up as `static/ui-kit.css` and give a 404. This task did not
change `server.py`, because other sessions are working on it. The change
that is needed:

```python
if u.path.startswith("/static/"):
    rel = os.path.normpath(urllib.parse.unquote(u.path[len("/static/"):]))
    if rel.startswith("..") or os.path.isabs(rel):
        return self.send_error(404)
    ctype = {"png": "image/png", "css": "text/css; charset=utf-8",
             "js": "application/javascript; charset=utf-8",
             "json": "application/json; charset=utf-8",
             "html": "text/html; charset=utf-8"}.get(rel.rsplit(".", 1)[-1], "application/octet-stream")
    return self.send_file(os.path.join(HERE, "static", rel), ctype)
```

Then:

- in `index.html`, add
  `<link rel="stylesheet" href="/static/ui/ui-kit.css">` before `app.css`;
- in `ui-kit.css`, the `url(sprites.png)` and `url(frames/...)` paths are
  relative to the CSS file, so they work unchanged;
- in `reborn.js`, replace its own quality table (`QCOL`, which does not
  match the game: Q1 is `#e8e8e8` and Q2 `#7fd0ff` there, the game uses
  #ffffff and #00fced) with
  `getComputedStyle(document.documentElement).getPropertyValue("--gw-q" + q)`
  or the `.gw-q<n>` classes.

Size: `static/ui/` is about 4.7 MB; `windows/` is 3.3 MB of it. The
`windows/` PNGs are reference pictures. Leave them out of the rsync if
bandwidth matters; the editor itself needs only `ui-kit.css`, `sprites.png`,
`frames/` and `zodiac/`.

## 10. How the reconstruction works, and its limits

`build_ui_kit.py` follows UI-SYSTEM §2-5:

- rectangles are `l,t,r,b` relative to the parent;
- `Template=` copies the template where it appears, and later attributes
  override it;
- a type-less element is only a group, so its children belong to its
  parent;
- children of a Tab are placed relative to the TabBar. Measured: only this
  makes the 3 x 5 paperdoll symmetric (42 px margins on both sides of a 288
  px window);
- buttons, tabs and check boxes draw row 0, and the selected tab draws row
  2;
- `TexturePos="1024,1024"` means no picture;
- `OnScaleX/Y` stretch the picture;
- window frames are 9-slices.

Choices made only for drawing [I]:

- TabBar, ListBox, Container and ScrollBar pictures are not drawn. Their
  `TexturePos="0,0"` would otherwise cover the skill window with the
  corner art.
- Of several overlapping help texts, only the first is drawn, because Lua
  shows one at a time.
- The item tooltip draws only the fill colour of its backgrounds, because
  the code sizes them to the text.
- Controls parked more than 60 px outside a window (bags II-IV) are left
  out of the picture, but they are in `windows.json`.

Not drawn: icons the code sets at run time (`icon.gwo` BtnTop pictures),
Lua-filled values, and hidden elements (`Visible="0"`; they are in
`windows.json` with `"visible": false`).

Not checked against the running game: the renders are compared with the
in-world frame `Reborn-Client/verification/06-in-world-later.png` only for
the HUD, chat tabs and skill bar style.
