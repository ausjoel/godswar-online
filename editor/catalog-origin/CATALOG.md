# Origin client catalogue (gwadmin-web `catalog-origin/`)

Generated by `build_origin_catalog.py` from the admin's Godswar Origin client (`GodsWar-2.51/Q20-Client/Client`). Do not edit by hand:
re-run the builder. Every name below is copied from the client's own English files; a few lookups the client
ships only in Chinese are translated and marked `translated` in `labels.json`.

Rebuild (Mac, needs Pillow and the client):

```sh
cd GodsWar-VPS/tools/gwadmin-web
python3 -I catalog_dbrefs.py --psql "ssh vps sudo -n -u postgres psql" --db godswar   # read-only snapshot of DB ids
python3 -I build_origin_catalog.py                                                     # catalogues, sprites, this file
```

Icons: `static/catalog-icons.png` holds every distinct icon of every catalogue as a 36 x 36 tile, 64 per row (1108 tiles). An entry's `sprite` = n is the tile at x = (n % 64) x 36, y = floor(n / 64) x 36. The old `icon` + `atlas` fields still point into `static/icons-origin.png` (4 atlases, 2 x 2) for the existing character sheet.

Item fields in plain English (for tooltips): `kind` = equipment slot family; `category` = what the item is (client weapon/armour group, or derived for consumables, see `category_source`); `slot` = equipment slot number (-1 = not wearable); `minlv`/`maxlv` = level range; `classes` = who may use it (empty = everyone); `camp` 0 Sparta / 1 Athens; `sex` 0 female / 1 male; `stack` = most per bag cell; `price` = shop sell value in Silver; `stats` = one value per quality Q1..Q10 (index 0 = Q1); `append_attributes` = the append attributes (`appendattrs.json` ids) this item may roll, i.e. what can go in its attribute rows; `forge` = the client's forge chain (next item, failure item, chance, costs); `use_skill` = skill cast when used; `teaches_skill` = skill a book teaches; `pet_skill` = pet skill a pet book teaches; `fractions` = the client's per-quality / per-grade tables (BaseFraction / AppFraction: the equipment-rank score an item adds at each quality / grade; ArmEffFraction + ArmEff and DefendFraction + DefendEff: weapon / armour rank score thresholds and the glow level each rank shows); `max_quality` / `max_grade` = the highest quality / grade this client has numbers for; `name_cn` = the client's name is Chinese.

**Quality and grade limits of this client.** the admin's Origin client lists stats for Q1-Q10 and grade scores for G1-G12 on ordinary gear (POINTS-AUDIT: forge Q10/G12), while the reborn database allows Q0-Q20 / G0-G25 and its own templates carry 20 / 25 values. Reborn's notes (`docs/client-reverse-engineering-notes.md`) say a quality or grade past the client's list can make the client fail the stat lookup or close while entering the scene, so the editor should warn above `max_quality` / `max_grade`.

## 4. Gaps and notes

* ItemBaseAttribute.xml defines 12 ids twice (10600, 10601, 10602, 10603, 10604, 10605, 10610, 10611, 10612, 10613, 10614, 10615); the later definition wins, like in the client.
* Map display names in the database (`map_templates.display_name`) are partly Chinese; the catalogue names every map from `QuestRegion.dat` by client scene id.
* 47 item names in `EquipName.dat` are still Chinese in this client (event collectibles and a few quest boxes, e.g. 3903 X200的外壳, 3904 X200的扬声器, 3905 X200的开关, 3906 X200的音频线); they are flagged `name_cn` and do not count as English in section 3.
* 321 of 1441 Magic.ini skill names are Chinese (item-use and monster skills the player never sees in a skill window); every player skill and skill book is English.
* Faith (`character_base.belief`) and guild duty names exist only in Chinese in this client (`Text/Belief.dat`, `Consortia_Job.ini`); `labels.json` gives the standard English names, marked translated.
* Status effect codes (`statuses.json` `effect_label`) are translated from the Chinese comments in Status.ini.
* Skill descriptions keep the client's value placeholders as `{Power1}` / `{Power2}`; the numbers are in the same entry (`power1`, `power2`). The client also scales them by skill level and zodiac grid.
* Ride.ini mount model names are Chinese (GBK); mounts are named by their item (`mounts.items`) and by their ride status (`mounts.rides`, from Status.ini).
* Monster stats (level, HP, damage) are not in the client; the database (`monster_templates.stats`, `medusa_monster_rules`) holds them. `monsters.json` gives names, maps, rank and model.
* Shops are not in the database: the reborn server compiles its NPC shop and cash-mall catalogues into its code. `shops.json` decodes them for display only.
* `quest_completed_ids` and the quest tables use the ids of `Text/Quest/<id>.dat`; 124 quests have text but no `Quest.xml` entry (no giver / level data).
* Live data check: 2 `character_items` row(s) already sit above this client's Q10 (Q20 x2) - see the quality limit note in section 1.
